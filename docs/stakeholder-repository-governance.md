# Stakeholder Content Repository — governance and usage

## Purpose
The Innovation Repository provides a protected knowledge-management space for stakeholder resources, reports, presentations and working documents. Repository content is separate from the public catalogue unless an administrator intentionally publishes equivalent structured ecosystem data elsewhere.

## Roles
- **SUPER_ADMIN**: national/platform oversight, all repository scopes, stakeholder-group administration.
- **PROVINCIAL_ADMIN**: manages groups and repository access within the assigned province.
- **ORG_ADMIN**: uploads and manages documents for the assigned organisation and groups in which the account participates.
- **CONTRIBUTOR**: uploads own documents and shares them only with permitted stakeholder groups or the assigned organisation.

## Access modes
- **GROUPS**: only members of explicitly selected stakeholder groups.
- **ORGANISATION**: users assigned to the same organisation.
- **PROVINCE**: signed-in stakeholders in the assigned province; administrator only.
- **ALL_STAKEHOLDERS**: any signed-in stakeholder; administrator only.

## File controls
Uploads use the platform's protected object-storage pipeline. Files are private by default, subject to size limits, magic-byte/content checks, malware scanning and audit logging. Supported repository formats include PDF, DOCX, XLSX, PPTX and approved image formats.

## Document lifecycle
Every repository document has title, description, category, tags, visibility, uploader, tenant scope and version metadata. A new version may supersede an earlier record; superseded versions remain auditable. Administrators and authorised owners can archive documents instead of deleting knowledge history.

## POPIA and confidentiality
Do not upload personal or special personal information unless there is a lawful purpose and the selected access group is appropriate. Administrators must review stakeholder membership regularly, disable departed users promptly and use the audit log for access/governance investigations.

## Administrator routine
1. Create stakeholder accounts under **Users & roles**.
2. Create groups under **Repository** (for example Steering Committee Members, Funding Partners, Innovation Support Hubs).
3. Add active stakeholder email addresses to each group.
4. Ask stakeholders to use **Account → Innovation Repository**.
5. Review repository/audit activity and remove access when responsibilities change.
6. Include repository backup/restore in normal disaster-recovery exercises.
